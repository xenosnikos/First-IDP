# Operational Scripts

- bootstrap-cluster.sh: One-time EKS namespace setup (Pulumi is primary)
- seed-secrets.sh: Initial AWS Secrets Manager seeding
- migrate-prod-to-argocd.sh: Phase 6 production migration (NOT READY)
- nebula-allow-login.sh / nebula-set-observer-key.sh / nebula-set-atlas-keys.sh / nebula-set-sentinel-key.sh / create-nebula-secret.sh: Nebula sign-in allowlist, Observer key, Atlas API keys (Digest-verified before storing; capacity §N5), staging sentinel READ key for the MCP endpoint (§N7), nebula SM blob (run with `!`; SM writes)
- staging-sentinel-bootstrap.sh: release-train staging tier one-time setup (SM `staging/twizz-sentinel` + `staging/twizz-admin`, ns `sentinel` on EKS-Moly-staging, admin k8s Secret mirror); `--rotate` mints new keys
- nebula-mcp-iam.sh (group nebula-mcp-users: self-service only + deny-all; `user <name>` = IAM user /nebula-mcp/<name> + one-time password) / nebula-mcp-bind.sh (NEBULA_MCP_IDENTITIES: login → google + aws) / nebula-fill-secrets.sh (staging sentinel key, staging API URL, Vercel): the Nebula MCP identity gate, docs/NEBULA.md §N7.1
- nebula-plo-access.sh (ECR keep-rule for `plo-*` images + PLO's read RBAC on staging/prod/nonprod; opens `list secrets` only in namespaces named with `--helm-namespaces <cluster>=<ns,..>`, sensitive ones need `PLO_HELM_ALLOW_SENSITIVE`; fails if the access entry carries any EKS access policy or the group can do more than intended; `--dry-run`, `--cluster-wide`) / nebula-set-plo-secrets.sh (mints the two lifecycle tokens into SM `nebula/plo`: publisher → Secret `plo-env`, dispatcher → Secret `plo-dispatch-env`, each read by PLO and the dashboard; stops if `preview/nebula` carries `LIFECYCLE_INGEST_TOKEN` or `LIFECYCLE_DISPATCH_TOKEN`; a secret scheduled for deletion is not "there" (legacy `preview/plo`) and not writable (`nebula/plo`: restore first), and a `describe-secret` error other than not-found stops the run; `--rotate`, `--remove-legacy-copy`) / nebula-set-plo-source-token.sh (validates and stores plo-source's dedicated fine-grained GitHub token in SM `nebula/plo-source-github`; refuses classic tokens and tokens that can see twizz-gitops): PLO CronJobs in Nebula, docs/NEBULA.md §N9. Stubbed tests: `bash scripts/tests/plo-scripts.test.sh`
